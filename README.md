# RAG-ассистент с векторной памятью

Минимальная, но работоспособная основа ассистента с архитектурой **RAG** (Retrieval-Augmented Generation): семантический поиск по векторному хранилищу + генерация ответа через внешнюю языковую модель.

## Возможности

- **CLI-интерфейс** — команды диагностики, загрузки URL и вопросов из терминала
- **Telegram-бот** — взаимодействие с ассистентом через Telegram
- **Загрузка документов из URL** — автоматическое извлечение текста из веб-страниц
- **Семантический поиск** — поиск по смыслу, а не по ключевым словам
- **Генерация ответов** — ответы на основе загруженных документов

## Архитектура

```
┌──────────────────┐       ┌──────────────────────┐
│  Пользовательский │       │      GenAPI          │
│     вопрос       │──────▶│  text-embedding-3-   │
└──────────────────┘       │       small          │
                           └──────────┬───────────┘
                                      │ вектор (1536)
                                      ▼
                           ┌──────────────────────┐
                           │      Pinecone        │
                           │  поиск похожих       │
                           │  фрагментов          │
                           └──────────┬───────────┘
                                      │ контекст
                                      ▼
                           ┌──────────────────────┐
                           │      GenAPI          │
                           │    gpt-4o-mini       │
                           │  (chat completions)  │
                           └──────────┬───────────┘
                                      │
                                      ▼
                           ┌──────────────────────┐
                           │       Ответ          │
                           └──────────────────────┘
```

### Как это работает

1. Вопрос пользователя преобразуется в числовой вектор (эмбеддинг).
2. Вектор сравнивается с сохранёнными векторами в Pinecone.
3. Наиболее похожие фрагменты возвращаются как контекст.
4. Языковая модель формирует ответ, используя найденный контекст.

## Требования

- **Python** 3.10 или выше
- **ОС**: Windows 10/11, Linux, macOS
- Доступ к **GenAPI** (языковая модель и эмбеддинги)
- Доступ к **Pinecone** (векторное хранилище)

**Windows (Bash / Git Bash):**
```bash
source .venv/Scripts/activate
```

**Linux / macOS:**
```bash
source .venv/bin/activate
```

### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 3. Настройка конфигурации

Скопируйте `.env.example` в `.env`:

```bash
cp .env.example .env
```

Откройте `.env` и заполните значения:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `GENAPI_API_KEY` | Ключ API GenAPI (общий) | — (обязательно) |
| `GENAPI_URL` | URL чат-эндпоинта (OpenAI-совместимый прокси) | `https://proxy.gen-api.ru/v1/chat/completions` |
| `MODEL_ID` | Модель для генерации ответа | `gpt-4o-mini` |
| `GENAPI_EMBEDDINGS_URL` | URL эмбеддингов (нативный API генераций) | `https://api.gen-api.ru/api/v1/networks/embeddings` |
| `EMBEDDING_MODEL` | Модель эмбеддингов | `text-embedding-3-small` |
| `PINECONE_API_KEY` | Ключ API Pinecone | — (обязательно) |
| `PINECONE_INDEX_NAME` | Имя индекса Pinecone | — (обязательно) |
| `PINECONE_PROXY_URL` | Прокси для Pinecone (только если требуется) | — |
| `TIMEOUT_GENAPI` | Таймаут запросов к GenAPI (сек) | `30` |
| `TIMEOUT_PINECONE` | Таймаут запросов к Pinecone (сек) | `30` |

> **Важно**: Никогда не добавляйте `.env` в систему контроля версий.

### Два эндпоинта GenAPI

GenAPI используется двумя разными способами:

- **Чат** (`GENAPI_URL`) — через OpenAI-совместимый прокси
  `https://proxy.gen-api.ru/v1/chat/completions`.
- **Эмбеддинги** (`GENAPI_EMBEDDINGS_URL`) — через **нативный API генераций**
  `https://api.gen-api.ru/api/v1/networks/embeddings`. Формат запроса и ответа
  здесь **отличается** от OpenAI:

  ```json
  // Запрос
  { "model": "text-embedding-3-small", "input": ["текст"], "is_sync": true }

  // Ответ (вектор в response.data[0].embedding)
  { "request_id": 123, "response": { "data": [ { "embedding": [ ...1536 чисел... ] } ] } }
  ```

  Прокси `proxy.gen-api.ru/v1/embeddings` для этой модели возвращает HTTP 500
  (`Missing credentials`) и не используется.

## Использование

### Запуск диагностики

```bash
python main.py
```

Приложение последовательно проверяет:
1. Загрузку конфигурации
2. Подключение к Pinecone
3. Существование и параметры индекса
4. Создание эмбеддинга тестового вопроса
5. Поиск в векторном хранилище
6. Генерацию ответа (при наличии результатов)

### Загрузка документов из URL

Для загрузки веб-страниц в Pinecone используется команда:

```bash
python main.py load <URL> [URL2] ...
```

**Пример (Bash / Git Bash):**
```bash
python main.py load https://example.com
```

**Пример (PowerShell):**
```powershell
python main.py load https://example.com
```

Загрузчик выполняет:
1. Проверку безопасности URL (защита от SSRF, проверка схемы)
2. Загрузку страницы с ограничением размера (5 МБ)
3. Извлечение основного текста из HTML (удаление скриптов, стилей, навигации)
4. Разбиение текста на фрагменты (по 500 слов, с перекрытием 50 слов)
5. Создание эмбеддингов и сохранение в Pinecone

Каждый фрагмент сохраняет метаданные:
- `text` — текст фрагмента
- `source_url` — исходный URL
- `page_title` — заголовок страницы
- `document_id` — уникальный ID документа (из MD5 URL)
- `chunk_index` — номер фрагмента

Можно загружать несколько URL за один запуск:
```bash
python main.py load https://example.com https://example.org
```

### Задать вопрос по загруженным документам

После загрузки документов можно задать вопрос:

```bash
python main.py ask "Вопрос"
```

**Пример (Bash / Git Bash):**
```bash
python main.py ask "Кто создал Python и когда?"
```

**Пример (PowerShell):**
```powershell
python main.py ask "Кто создал Python и когда?"
```

Команда выполняет полный цикл RAG:
1. Создаёт эмбеддинг вопроса
2. Ищет релевантные фрагменты в Pinecone
3. Показывает найденные фрагменты с оценками релевантности
4. Показывает уникальные URL источников
5. Генерирует ответ на основе найденного контекста
6. Если в контексте нет ответа — честно сообщает об этом

Можно задать вопрос по любым загруженным документам, даже если они были загружены ранее — векторы сохраняются в Pinecone.

### GET-запросы к открытым API

В проекте есть модуль `api_client.py` — универсальный GET-клиент для
работы с любыми открытыми REST API (jsonplaceholder, open-meteo,
REST Countries и др.).

Поддерживает:
- Таймаут запроса (по умолчанию 15 с)
- Обработку HTTP-ошибок (404, 500, 401 и др.)
- Валидацию JSON-ответа
- Параметры запроса (query string)
- Пользовательские заголовки
- Контекстный менеджер (`with`)

```bash
python main.py api get <URL>
python main.py api test       # тестовый запрос к jsonplaceholder
```

**Пример — получение одного поста:**

```bash
python main.py api get "https://jsonplaceholder.typicode.com/posts/1"
```

**Пример — список пользователей с лимитом:**

```bash
python main.py api get "https://jsonplaceholder.typicode.com/users?_limit=3"
```

**Пример — тестовый запрос:**

```bash
python main.py api test
```

**Использование в коде (Python):**

```python
from api_client import APIClient, APIError

# Контекстный менеджер (автоматически закрывает сессию)
with APIClient(timeout=10) as client:
    response = client.get("https://jsonplaceholder.typicode.com/posts/1")
    if response.success:
        print(response.data["title"])

# Быстрая функция-обёртка
from api_client import fetch_data
response = fetch_data("https://jsonplaceholder.typicode.com/posts/1")
print(response.data["title"])

# С параметрами и заголовками
response = client.get(
    "https://jsonplaceholder.typicode.com/posts",
    params={"_limit": 3, "_sort": "id"},
    headers={"Accept": "application/json"},
)

# Обработка ошибок
try:
    data = client.get_or_raise("https://jsonplaceholder.typicode.com/posts/999")
except APIError as exc:
    print(f"Ошибка: {exc}")  # "HTTP 404: ..."
```

### Telegram-бот

Бот позволяет взаимодействовать с RAG-ассистентом через Telegram.

#### Команды бота

| Команда | Описание |
|---------|----------|
| `/start` | Приветствие и список возможностей |
| `/add_url <URL>` | Загрузить веб-страницу для поиска |
| `/search <вопрос>` | Задать вопрос по загруженным документам |

Также можно отправить обычное сообщение с вопросом — бот ответит.

#### Настройка бота

1. **Создайте бота через @BotFather:**
   - Найдите `@BotFather` в Telegram
   - Отправьте команду `/newbot`
   - Укажите имя бота и username (должен заканчиваться на `_bot`)
   - Скопируйте полученный токен (формат: `1234567890:ABCdefGHIjklMNOpqrsTUVwxyz`)

2. **Добавьте токен в `.env`:**
   ```
   TELEGRAM_BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz
   ```

3. **Если требуется прокси для доступа к Telegram API:**
   ```
   PROXY_URL=user:password@proxy-host:port
   ```
   Схема `http://` добавляется автоматически.

4. **Запустите бота:**

   **Bash / Git Bash:**
   ```bash
   source .venv/Scripts/activate
   python main.py bot
   ```

   **PowerShell:**
   ```powershell
   .\.venv\Scripts\Activate.ps1
   python main.py bot
   ```

5. **Проверьте бота** — отправьте ему `/start`.

### Безопасность

- Проверка TLS-сертификатов не отключается

### Безопасность загрузчика документов

- **SSRF-защита**: блокируются обращения к localhost, приватным IP (127.0.0.1, 192.168.x.x, 10.x.x.x, 172.16-31.x.x), link-local и служебным адресам
- **Проверка DNS**: адрес проверяется после разрешения имени хоста
- **Перенаправления**: проверяется целевой адрес каждого редиректа, максимум 3 перехода
- **Схема URL**: разрешены только http:// и https://
- **Размер ответа**: максимум 5 МБ
- **Время ожидания**: таймаут 15 секунд
- **Тип содержимого**: обрабатывается только text/html, text/plain, application/xhtml+xml

## Диагностика типичных ошибок

### «Отсутствуют обязательные переменные окружения»

Файл `.env` не создан или в нём не заполнены ключи. Скопируйте `.env.example` в `.env` и укажите значения.

### «Ошибка подключения к Pinecone»

- Проверьте, что `PINECONE_API_KEY` верен
- Убедитесь, что индекс с именем `PINECONE_INDEX_NAME` существует
- Проверьте доступность сети

### `[WinError 10054] Удаленный хост принудительно разорвал соединение`

Соединение с data-plane индекса Pinecone разрывается на уровне сети. При этом
`describe_index_stats` (небольшой запрос) может проходить, а `query` (крупный
POST с вектором) — падать. Решение: указать рабочий прокси в `.env`:

```
PINECONE_PROXY_URL=http://user:password@host:port
```

Прокси применяется **только** к Pinecone (data-plane) и не влияет на GenAPI.
Не придумывайте адрес прокси — используйте фактическое значение из вашей
сетевой конфигурации.

### «Ошибка генерации эмбеддинга»

- Проверьте `GENAPI_API_KEY`
- Убедитесь, что `GENAPI_EMBEDDINGS_URL` указывает на **нативный** эндпоинт
  `https://api.gen-api.ru/api/v1/networks/embeddings`
- Проверьте баланс на аккаунте GenAPI

### HTTP 500 `Missing credentials` при запросе эмбеддингов

Признак того, что запрос ушёл на OpenAI-совместимый прокси
(`proxy.gen-api.ru/v1/embeddings`), у которого не настроена маршрутизация
модели эмбеддингов. Используйте нативный эндпоинт
`GENAPI_EMBEDDINGS_URL=https://api.gen-api.ru/api/v1/networks/embeddings`.

### «Совпадений не найдено»

Индекс существует и соединение исправно, но в нём нет данных или запрос не имеет семантического совпадения. Проект только читает существующие векторы; их загрузка — внешний процесс.

## Известные ограничения

- Загрузчик документов обрабатывает только HTML и текстовые страницы. PDF, изображения и другие форматы не поддерживаются.
- Извлечение текста из HTML использует базевые эвристики (BeautifulSoup) и не всегда корректно работает со сложными страницами.
- Для загрузки URL требуется, чтобы индекс Pinecone уже существовал.
- Проект не имеет Telegram-интеграции или веб-интерфейса — только консольные команды.
- Прокси Pinecone должен быть указан с явной схемой (`http://` или `https://`).

### «Размерность эмбеддинга не совпадает»

Используемая модель эмбеддингов должна создавать векторы той же размерности, что и индекс Pinecone. Для `text-embedding-3-small` это **1536**.

## Ограничения текущей версии

- Только конфигурация, подключение, поиск и генерация ответа
- Нет загрузки документов и URL
- Нет Telegram-бота
- Нет парсинга HTML
- Нет автоматического веб-поиска
- Нет сложной агентной архитектуры
- Нет инструмента загрузки пользовательских документов
- Структура подготовлена к расширению, но незапрошенная функциональность не реализована
